# tinfirm-web

The Tinfirm single-page app: Angular 22 (standalone, zoneless, signals, OnPush), Tailwind 4 and
spartan/ui, on the redesigned API (`../api/openapi.yaml` 0.6.0). It was rebuilt slice by slice after
[the web plan](../docs/reviews/2026-10-12-web-plan.md) (§7), from W0, "Foundation", to W7,
"Governance"; agent memory ([ADR-0063](../docs/adr/0063-agent-memory.md)), the skills library
([ADR-0064](../docs/adr/0064-skills-library.md)) and error reports
([ADR-0070](../docs/adr/0070-error-reports.md)) came after. The binding rules are in
[`docs/CONVENTIONS.md`](../docs/CONVENTIONS.md) §5, §6 and §11, the look in [DESIGN.md](../DESIGN.md).

## Layout

- `src/app/api/` – `generated/` client (never edit, never hand-write DTOs); `problem.ts` (RFC 9457 problems to messages and form errors, the codes of CONVENTIONS §6 and §15 and of the licence (ADR-0077: `SEATS_EXHAUSTED` and `EDITION_REQUIRED` worded from their `details` on every page, before a page's own message for a `403`), `credentialMatches` and `problemReason` for the extension members the contract's `Problem` does not declare); `run-events.ts` (the `RunEvent.payload` shapes of runner protocol v2).
- `src/app/core/` – session and the auth guards; `permissions.ts` (the four roles OWNER, ADMIN, MEMBER and VIEWER (ADR-0077), `managesCompany`, `isMember`, `mayWork` (every member but a Viewer), `isViewer`, `holdsSeat`, and the server's own answers `usableByMe`, `editableByMe`, `mayDecide`); `company-guards.ts` (`companyAdminGuard`, `companyMemberGuard`, `companyWorkerGuard` for the pages that start work); `licence.ts` (`LicenceState`: `GET /api/licence` once a session, `has(feature)` for what the pages hide, ADR-0077); `current-company.ts`; `caller-principal.ts` (the caller's principal and model access, from `getMyModelAccess`: plan §9, gap 2); `inbox-counts.ts` (the sidebar's badge); `submission-key.ts` (package R's `Idempotency-Key`: `SubmissionKey` makes a key per submission with `crypto.randomUUID()` and keeps it while the same submission is sent again after a failure on the way; `submitWithKey` sends one and settles its key); `error-reports.ts` (the browser's errors, sent to the server's error reports: ADR-0070); `kill-switch-state.ts` (the company's stop, for the banner); theme, polling, paged resources, notifications.
- `src/app/shell/` – the sidebar layout. `navigation.ts` is the one table of the company's navigation (plan §3): the routes' guards, the sidebar and the company switcher all follow it.
- `src/app/pages/` – one folder per route: `login/`, `authorize/` (the OAuth consent page), `link/` (a chat user's sign-in link), `home/`, `me/`, `admin/` and `company/` (one folder per page of a company), and `not-found.ts`.
- `src/app/shared/` – the shared patterns (below), page header, error and loading states, Markdown, the editor, `segmented`, time, `labels.ts` (the design's nouns in words: runtimes, system kinds, access, tool modes and effects, runner hosts, money), `logo.ts` (the Ti mark and the wordmark), `memory-notes.ts` (an agent's notes for a person or a trigger, ADR-0063), `run-status`, `queue-reason` (the server's sentence, its time and a link to the fix), `waiting-on`, `role-badge`, `sign-in-result` (what the accounts' OAuth callback says, `?account=`: `signInReturn()` reads it once and drops it, `signInReturnTo()` is where a sign-in comes back to), `token-hints` (the token each kind of system takes, and a refusal in the system's words), `runner-hosts/` (a host's card, its capacity select and the registration dialog with its token shown once, for a personal or a company host), and `files/` (sizes, download links, the preview dialog of ADR-0047).
- `src/app/testing/` – spec helpers (`provideTestHttp`, `settle`, `fakeCurrentCompany`, `typeInto`), the fake `EventSource`, and `fixtures/`: typed test data built from the generated models, one file per tag (`me`, `members`, `systems`, `accounts`, `model-access`, `agents`, `skills`, `runs`, `conversations`, `inbox`, `triggers`, `chats`, `governance`, and `ids` for the ids they share), each builder taking the overrides a case needs. The cast borrows names from the e2e seed but is not the seed: Acme, Alice, Carol and Dave, the group Analysts, GitHub and Jira are the seed's; the fixtures' owner is Olga and their admin Bob (in the seed, Olivia and Adam, and Bob a member), their service account svc-reader (in the seed, svc-dev), and their agent Business analyst, shared with Analysts (in the seed, Analyst, shared with Everyone).
- `src/app/ui/` – spartan/ui helm components, generated with `ng g @spartan-ng/cli:ui <name>`. We own and may edit them. spartan/ui's MIT licence and copyright notice stay with them in `src/app/ui/LICENSE`; the server image adds it to the web bundle's third-party notices, `/licenses/THIRD-PARTY-web.txt` ([ADR-0082](../docs/adr/0082-licence-notices-and-dependency-licences.md)).
- `scripts/` – the screenshot script and its mocked API (`mock-api.ts`, from the fixtures).

## Shared patterns (plan §2, §10 question 1)

- **`app-who-acts-who-pays`** (`shared/who-acts-who-pays.ts`, words in `who-acts-who-pays-view.ts`): who acts on each system, who pays and where it runs, before work starts and while it runs. It draws from an `AgentReadiness` (with the reader's model access and accounts), a `Conversation` (its bindings' own sentences, its payer, its last turn's host), a `Run`, or a ready `view` (a trigger's preview, package 4). Orange only on what the reader can act on. The new conversation page, the conversation page (in full, and as one line in its head: `app-who-acts-who-pays-line`), the run page, an agent's page and settings, and a trigger's editor, preview and page use it.
- **`app-binding-card`** (`shared/binding-card.ts`): the Connect card of a waiting binding, by `reason`, every reason of the contract: connect (sign in, returning to the page, or paste the token the system's kind takes, then `continueConversationBinding`), sign in again, pick a grant or connect one's own instead, and the neutral cards of an admin to wait for, a switched-off system, a trigger's author who lost a right, or a binding that is gone (with "Start a new conversation"). Its inputs: the binding, the company, the conversation, the agent's name and id, `signInAvailable` (the system's `MyAccount.oauthAvailable`), `mine` and `personName` (the Owner reading someone else's), `returnTo`; it emits the binding as the server answered (`changed`). Back from a sign-in, the page reads `signInReturn()` and calls `continueBindingAfterSignIn()`.
- **`app-widening-card`** (`pages/company/agents/widening-card.ts`): what an agent's new version adds (systems, tools with their mode and what they were, repositories with their access, hosts) and "Accept version N", which names the version shown. Orange: only the reader can accept. It emits `accepted` with the reader's settings after `acceptAgentVersion`; the page reads the agent (and its readiness) again. The agent page and the settings page show it; W4's new conversation page shows it too.
- **`app-agent-settings-form`** (`shared/agent-settings-form.ts`, its model in `agent-settings-model.ts`): one agent's settings, for a person (the settings page) or, with `subject="trigger"`, a trigger (W5). It edits a `SettingsDraft` (`[(draft)]`, from `settingsDraftOf(AgentSettings)`; `settingsRequest(draft)` is the body of `putMyAgentSettings` or `saveTriggerSettings`) and saves nothing itself. Inputs: the agent and its `widening` (tools a version the reader has not accepted adds are marked pending), the reader's `subscriptions`, `allowSubscriptions` (false when the payer is not the author), `gatewayModels`, `allowedModels` and `modelsUnavailable` (the reason that disables the model), `ownServers`, `ownServersAllowed` and `ownServersNote` (false while a trigger acts as someone else), `errors` and `errorAt` (`settingsFailure(error)` maps a failed save; `errorAt` is the system or tool an `UNKNOWN_TOOL` or `SYSTEM_NOT_ON_AGENT` names in its `details`, said where it stands), `disabled`. A tool of the agent offers "As the agent says", "Ask me" or "Off", never "Allowed" (I4); `askOnEveryWrite` prefills "Ask" on every write for a trigger anyone may drive. A mode the reader picks on one of their own servers' tools carries the effect the row showed (`chosenForEffect`), as the agent editor does for the owner: one save confirms an "Allowed" whose tool became a write (I19).
- **`app-decision-card`** (`shared/decision-card.ts`): a question, or an approval by subject (a tool call with its system, the account it runs as and its arguments folded; a repository, read or write; a host; a change request; a trigger's result to review, sent back only with a note), "for good" only for whoever may edit the agent, "Waiting for …" (the person or the trigger's team) without `mayDecide`. One `Idempotency-Key` per submission (`core/submission-key.ts`), kept on a retry.
- **`app-pinned-cards`** (`shared/pinned-cards.ts`, W4b): a conversation's open cards above the composer, for W4a's page: the decisions the reader decides and the bindings they act on, the oldest open, the others folded; outputs `decided`, `outdated`, `bindingChanged` and `jump` (where a card was raised).
- **Governance (W7)**: `app-kill-switch-banner` (the company layout shows it above every page from `core/kill-switch-state.ts`), `app-reason-dialog` (a confirmation that asks why), `shared/governance-labels.ts` (the words of switches, spend, departures, retention and erasure). For the conversation page (W4a): `app-conversation-reads-button` and `app-conversation-reads` (`shared/conversation-reads.ts`; inputs `companyId`, `conversationId`; who else read it, for its person: the eye button on the page's line of who acts and who pays, the list in its details sheet on a phone) and `app-client-badge` (`shared/client-badge.ts`; input `origin`; "AI client" for `CLIENT`, nothing otherwise).

## The licence, editions and the Viewer (ADR-0077)

One key covers the instance, and one key is in force at a time: seats added during the year come as the licence's next revision, which replaces it, and a renewal's key waits as the next key until its start. `LicenceState` (`core/licence.ts`) reads `GET /api/licence` once a session, again every 15 minutes in a company, and after the licence page enters a key. Every gate is the server's: the app only hides what the server refuses, and a feature counts as in force until the licence is read.

- **`app-licence-banner`** (`shared/licence-banner.ts`, words in `shared/licence-labels.ts`): the company layout shows it above every page to Owners, Admins and instance admins: EXPIRING with the days left and the day, GRACE with the day the paid features stop, EXPIRED with what stopped and what stays (decision 7). An instance admin gets the link to `/admin/licence`.
- **`app-edition-badge`** (`shared/edition-badge.ts`): "Pro" or "Enterprise" beside a feature the licence does not hold, with the sentence of `403 EDITION_REQUIRED` for a screen reader. The Outlook add-in's manifest, the audit's filters, export, verification and daily checks (the export kept until `auditExportUntil`), retention's own periods (read-only otherwise), setting a legal hold (lifting one stays), and several companies say so.
- **`app-viewer-notice`** (`shared/viewer-notice.ts`): a Viewer holds no seat and never starts or continues a conversation, owns or edits an agent, authors a trigger, or answers or decides a request. The inbox, conversations, agents and triggers say so in place of their New buttons, and the conversation page in place of its composer; `companyWorkerGuard` keeps a Viewer off the pages that start work (a new conversation, agent, skill or trigger, one's agent settings) and off Accounts. Decisions follow the server's `mayDecide`.

## A system's credentials (ADR-0072)

The web app calls service identities **service accounts**; the routes, the API and the code keep `serviceIdentity`.

- **`app-system-credentials`** (`pages/company/systems/system-credentials.ts`, words in `credential-labels.ts`): a company system's credentials on its Overview, for OWNER and ADMIN (never a personal server, nor a webhook): each with its state, who it is at the system, who connected it, the groups it is lent to (`READ`/`WRITE` pills, `createGrant`/`updateGrant`/`deleteGrant`) and the service accounts that borrow it (`lendSystemCredential`/`withdrawSystemCredential`), each lent since when and, for a service account, how many of its triggers act with it (Withdraw and Remove say how many pause; none, nothing pauses); Add credential, Store a new token or Sign in again, Rename, Disable or Enable, Remove; how many members hold their own account there (`memberAccounts`). A chat system's bot is marked and managed under Bot only. Each credential is a fragment (`#credential-{id}`) that the inbox, a departure and a service account link to. It emits the credentials it read (`credentials`), for the tools' and the test's choice of credential.
- **`app-credential-dialog`** (`credential-dialog.ts`): add a credential (a name, then a token or a sign-in with the system's app that comes back to the page), or give one a new token or sign it in again. The tools section opens it too, when a refresh answers `credentialRequired` without `withAccount`, and reads the tools again with the new credential.
- **`app-credential-lend-dialog`** (`credential-lend-dialog.ts`): lend a credential to a group or a service account; for a service account it says which credential this one replaces on the system (one per system) and how many of its triggers acting with that one pause.
- **`app-identity-credentials`** (`pages/company/service-identities/identity-credentials.ts`): what a service account borrows, read-only, with the access, since when and how many of its triggers act with it, each linking to the credential on its system's page.

## The conversation page's side column (W4c)

W4a's conversation page hosts these in its side column; each reads only its inputs.

- **`app-conversation-outputs`** (`pages/company/conversations/conversation-outputs.ts`): inputs `companyId`, `conversationId`, `outputs` and `attachments` (`Conversation.outputs`, `.attachments`), `turns` (`Conversation.turns`, for "From turn N"). Change requests with their state at the code host, documents previewed in place and downloaded, links; an output or a document's file that retention purged says so.
- **`app-conversation-files`** (`pages/company/conversations/conversation-files.ts`): inputs `companyId`, `conversationId`, `attachments`, `mine` (the reader is its person), `personName`, `ended`, `mayAcknowledge` (OWNER or ADMIN, ADR-0014); outputs `added` (the stored `Attachment`) and `deleted` (its id), after which the page reads the conversation again. Each upload sends an `Idempotency-Key` of its own (package R), the same one when it is retried after a transport or server failure; `CREDENTIAL_FOUND` names what matched; an output's document offers no delete (`ATTACHMENT_IS_OUTPUT`); a purged file offers no preview or download, and a `410` says why.

## Triggers (W5)

`pages/company/triggers/` builds package 4's pages (plan §4.5, §7's W5 row):

- **The list** (`triggers.ts`): each trigger's sentence, why it is paused or waits (`trigger-state-chips.ts`, neutral), its author, team, payer and last firing; `?status=` filters.
- **The editor** (`trigger-editor.ts`, its model in `trigger-draft.ts`): When (`trigger-when-fields.ts`: an issue on a tracker, a mention in chat channels picked with `trigger-channels-field.ts`, a webhook's mapped events and conditions on its body, or a schedule), the agent and instruction, Acts as and pays (`trigger-accounts-fields.ts`: the one choice fills the account table, the source's row required), the settings (`app-agent-settings-form` with `subject="trigger"`, "Ask" prefilled once when anyone may drive it), the team, Results (`trigger-results-fields.ts`). The preview (`trigger-preview-panel.ts`, words in `trigger-view.ts`) is read after every change, always as if acknowledged so that the server answers `openToAnyone`; Save waits for the preview and, while a row is the author's own and a write runs, for "I understand" (V14). Refusals are placed by `trigger-errors.ts`. A change sends `updateTrigger`, `replaceTriggerAccounts` and `saveTriggerSettings`, each only when changed.
- **The trigger page** (`trigger-page.ts`): who acts and pays, the rule, the results and the review switch, the firings (`trigger-firings.ts`), Run now for a tracker or a schedule (`run-now-dialog.ts`, with the subject search and the 409s worded; a mention or a delivery fires the others), Pause and Resume, a new agent version to accept (`trigger-widening-card.ts`), Reassign (`reassign-dialog.ts`, admins) and Delete.
- **For other pages**: `identity-triggers.ts` on a service account's page, `system-triggers.ts` (triggers and polls) on a tracker system's page, `inbox-trigger-item.ts` for the inbox (W4b), and in `conversation/` for the conversation page (W4a): `app-external-message` (an `EXTERNAL` comment, or a webhook's delivery) and `app-tracker-place-notice` (where a trigger's conversation lives; what its composer takes follows `Conversation.mayPost` and `mayAnswer`). The review of a `RESULT` approval (approve, or return with a note) is `app-result-review-card`, in `shared/result-review-card.ts`.

## The conversation pages (W4a, plan §4.1 and §4.2)

`pages/company/conversations/`:

- `new-conversation.ts` – `conversations/new?agentId=&subjectSystemId=&subjectKey=`: the agent (those the reader may use), who acts and who pays from its readiness with what holds it (nobody can pay: Start is off; the first turn would wait; no host now), the widening card, "Connect now, or when the agent first needs it" (`connect-now.ts`: sign in or paste a token), the subject, the repositories preset from the settings, the first message, and Start (an idempotent submission).
- `conversation-page.ts` – `conversations/:conversationId`: `ConversationHeader` (rename in place, key and branch, the agent, the subject chip, the state chip, W6's `app-chat-place`, W7's `app-client-badge`, the menu with Cancel turn, Retry (Continue after a turn stopped at its time limit) and End conversation), who acts and who pays as one line (`app-who-acts-who-pays-line`, with its "Details", which opens the full panel above the thread, and for its person W7's `app-conversation-reads-button`), the thread (`MessageList`: each finished turn as `ConversationTurn` with its work folded into one row ("Worked for 6m 12s", `TurnWork`), its answer and its status line, W4b's `app-decision-card` where a turn raised a decision, the turn running now as `LiveTurn`), `ConversationStatus` (failed with Retry and its fix, cancelled, a paused agent, ended), `ConversationCards` (the Connect cards) and the `Composer`, sticky at the foot (or `OwnerNotice`, the banner in its place for the Owner reading someone else's), with W4b's `app-pinned-cards` above it while the reader, scrolled past the thread's start, has their open cards in the thread (`[data-open-card]`, watched with an `IntersectionObserver`) out of view (above the thread, pinned cards would push the composer off the screen); "Where it was raised" scrolls to the card. ## Notes

- Authentication is the server's session cookie. Angular's built-in XSRF support sends `X-XSRF-TOKEN` from the `XSRF-TOKEN` cookie on every mutating call; the login page calls `GET /api/auth/providers` first so the cookie exists.
- The app runs under the server's strict CSP: no inline scripts, and critical-CSS inlining is off in `angular.json`. The fonts are bundled (`@fontsource-variable/figtree`, `@fontsource/dm-mono`), no CDN.
- `<hlm-field-error>` inside an `hlmField` shows only while the field's control is invalid, which `[formField]` of a signal form reports. An error the page sets itself (a select outside a form, a check made before sending, the server's answer kept in a signal) stays hidden unless the element has `forceShow`; the credential dialogs of a system's page do so.
- Untrusted Markdown (agent output, messages, documents) is rendered with `renderMarkdown()` and bound with `[innerHTML]`, so Angular's sanitizer always runs; raw HTML in the source is shown as text. Never use `bypassSecurityTrust*` for it (ADR-0047).
- A file is never rendered as HTML, in a frame or otherwise: the preview shows text through bindings, Markdown through the renderer, and images through `img` from the download URL (ADR-0047).
- The accounts' OAuth callback returns to the page that started the sign-in with `?account=connected&system=` or `?account={reason}`; when it cannot tell the page it returns to `/`, which opens Accounts with the message in the first company (W1).
