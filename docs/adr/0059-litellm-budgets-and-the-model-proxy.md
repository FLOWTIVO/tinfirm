## Context

- The owner wants model spend per person: the same agent used by several people is paid by each of them, and a trigger by what its author chose (ADR-0058).
- A model credential belonged to an agent (ADR-0027, ADR-0042): a provider's key or a gateway's key, or a runner credential that is one member's subscription on their host. The person using the agent never counted, and a member's subscription could serve other members' work.
- `run.assign.modelAccess` already carries a key and a base URL per run, so the server can choose the key per run; but the runner host put the key into the sandbox's environment, where a prompt-injected agent can read and send it (R23, 7.13), and any runner host of the company could receive any key, whoever runs the host.

## Decision

1. **LiteLLM is the mandatory model gateway.** Bundled with Tinfirm by default (Helm chart, Compose), or a company's existing proxy with an admin key. Tinfirm manages it through its admin API; the company's provider keys and model list live in LiteLLM.
2. **One LiteLLM virtual key per principal** (member or service identity), with the principal's budget and models, created and kept in Tinfirm's vault; the principal never sees it. **The key never leaves the server** (decided after the design record's security review, row 21): LiteLLM stays inside the deployment, and the server is the runner hosts' model endpoint. A run's `modelAccess` carries the server's model relay as `baseUrl` (`{TINFIRM_PUBLIC_URL}/api/runner/v1/model/…`, in the `ANTHROPIC` or `OPENAI` format) and a **one-run token** as `apiKey`; the server accepts the token only while its run is active on its host, removes LiteLLM's own request fields (an upstream URL, credentials, metadata and the like) from the body, and forwards the request to LiteLLM with the paying principal's key, streaming the answer back. Budgets: a company default per member, overridden per person, set per service identity. A spent budget fails the run (`USAGE_LIMIT`) and the principal's conversations wait; Tinfirm never switches to another payer. *Amended 2026-10-27 (M1, D8 of the security review of that day): the provider is a channel for what the model emits, never a relay the agent directs. The relay, and the model port with it, removes `mcp_servers` and `container` and refuses `400` a request that defines a tool the provider would run (a remote MCP server, code execution, web fetch or search), unless the company's `providerTools` is `WEB_SEARCH`, which lets the providers' web search through and nothing else (amended again 2026-11-06 by [ADR-0108](0108-no-provider-run-tools.md): every provider-run tool is refused, `mcp_servers` and `container` included, and `providerTools` is gone); it passes only the `anthropic-beta` and `OpenAI-Beta` values on its lists.*
3. **Model access is never granted to groups.** A person's conversation is paid by the person; a trigger by the model access its author named (their own, or a service identity's they may use).
4. **Subscriptions are the one exception** to the gateway: a member's Claude or ChatGPT subscription on their own runner host serves only that member's own conversations and the triggers whose model access is theirs, routed to that host by `credentialLabel`. LiteLLM does not meter it. *Amended by ADR-0085, decision 7: by default a trigger pays with its payer's budget and a subscription serves the member's own conversations only; the company's switch `triggerSubscriptions` restores the triggers' clause for that company.*
5. **The runner's model proxy.** The runner host starts a listener per run, on the sandbox network's gateway, plain HTTP behind a random per-run secret path, and stops it when the run ends. The runtime gets the listener as its base URL and a dummy key; the host forwards the model API's endpoints only (messages, responses, chat completions, models) to the gateway over https, replaces every credential header the sandbox sends with the real key, streams the answer back, scans it for the key, and refuses WebSocket upgrades. A run whose proxy cannot start fails rather than give the sandbox the key. Codex gets the gateway as its own provider with WebSockets off. Always on for a gateway's runs, with no option to turn it off (the owner's decision after the security review): the server cannot tell whether a host proxies, since the protocol does not change, so the host must never be able to send the key into the sandbox.
6. **Company and personal runner hosts.** Company hosts, registered by admins, run any conversation. Personal hosts, registered by a member, run only conversations whose credentials are all their owner's: their model access and their own accounts. A personal host never receives a key; the rule protects what a host's owner can see of a run (its prompt, workspace and transcript).

## Consequences

- No provider key and no LiteLLM key reaches a runner host or a sandbox: a host holds only its run's one-run token, which the model proxy keeps out of the sandbox and which is worthless once the run ends, and away from its host: from runner host 0.3.0 the model proxy sends the host's own token with it, to the server's origin only, and the relay takes the run's token only with the token of the host the run is assigned to (package 2's open point 6; hosts of 0.2.x are accepted without it until the operator sets `TINFIRM_MODEL_RELAY_REQUIRE_HOST_TOKEN`). LiteLLM is never exposed beyond the deployment; runner hosts reach only the Tinfirm server, as they already do. R23 is retired. A runner host older than the always-on proxy would put the one-run token in the sandbox, so the server sends gateway runs only to hosts whose `hello.runnerVersion` has the always-on proxy (a field the protocol already carries).
- Spend is attributed and capped per principal at one point; usage per agent, trigger and conversation comes from the runs' usage events.
- A company needs a LiteLLM; Tinfirm ships one. Runtimes reach any model the gateway serves in the Anthropic or OpenAI format, and each principal's key must allow the small models runtimes call on their own (OpenCode titles a session with a small model).
- Verified on 2026-10-12 with the images' pinned Claude Code, Codex, pi and OpenCode over ACP, through the Rust listener in front of a mock gateway that accepts only the real key.
- A gateway on the runner host's own machine is refused by the proxy's address rules unless the operator names it explicitly (planned option).

## Alternatives considered

- **A per-run LiteLLM key** created at assignment and deleted at the end: the key is still in the sandbox until the run ends, every run costs two admin calls, and a budget across a principal's many keys needs LiteLLM's user budgets. Replaced by the proxy, which keeps the key out of the sandbox entirely and lets the budget sit on one key.
- **The egress proxy rewriting headers.** It tunnels https without reading it; TLS interception was rejected in ADR-0044 (a CA in every sandbox).
- **Runner hosts reaching LiteLLM directly** (the first form of this decision): LiteLLM exposed to runner hosts behind a path filter, each host holding the keys of the principals it runs, and LiteLLM's own request fields arriving from the sandbox unfiltered. Replaced by the server relay after the design record's security review (row 21): the relay costs the server the model streams (long-lived, low bandwidth, beside the tool calls it already carries).
- **People's own provider keys through LiteLLM** (a model per team or user with the person's key). Considered; the owner chose budgets on the company's provider keys.
- **Model keys granted to groups, or a company fallback in conversations.** Rejected: nobody pays for someone else's conversation without choosing to.
