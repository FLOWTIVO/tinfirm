# ADR-0090: The Helm chart runs on any conformant cluster, with defaults that need no knowledge of it

- Status: Accepted
- Date: 2026-10-24
- Decided by: the owner
- Sources: [ADR-0080](0080-helm-chart-published-to-ghcr.md) (the published chart); the public guide [Install on Kubernetes with Helm](../../docs-site/content/operator-guide/helm.md); [helm.md](../operations/helm.md); the [threat model](../threat-model.md), 1.5, 4.5 and 8.8; Kubernetes' Pod Security Standards; the Gateway API `v1`; the Prometheus Operator's `PodMonitor`
- Amends: [ADR-0080](0080-helm-chart-published-to-ghcr.md), its consequence that a chart published for `main` defaults to an image that does not exist
- Amended by: [ADR-0091](0091-image-tag-alone.md), under which `image.tag` is the image tag's one name (decision 7)
- Changes: in `deploy/helm/tinfirm`, the values `image.tag`, `httpRoute.*`, `metrics.podMonitor.*`, `openshift`, `networkPolicy.egress.systems` and `litellm.tmpVolume`, the templates `httproute.yaml` and `podmonitor.yaml`, the defaults of `networkPolicy.ingress.controller`, `trustedProxies` and `litellm.image`, `litellm.podSecurityContext` and `litellm.securityContext`, the helpers `tinfirm.imageTag`, `tinfirm.openshift`, `tinfirm.securityContext` and `tinfirm.networkPolicy.dnsEgress`, and `ci/gateway-api-values.yaml` and `ci/openshift-values.yaml`; Compose's `litellm` service; `ci.yml`'s `publish` (`app-version`) and its LiteLLM pin check

## Context

The chart is public (ADR-0080) and its defaults carried assumptions that do not hold on every cluster:

- **The NetworkPolicy admitted ingress-nginx alone to port 8080.** On a cluster with another controller, a Gateway or a cloud load balancer that sends to the pods, the server was unreachable until the operator found the cause; the fix many operators reach for is `networkPolicy.enabled: false`, which drops the egress rules and LiteLLM's isolation with it. Upstream ended ingress-nginx's maintenance in March 2026 and points to the Gateway API instead.
- **Egress opened port 443 only with OIDC providers.** With local sign-in only, every call to Jira, GitHub, Slack or the error tracker timed out until the operator added a rule; LiteLLM's policy, by contrast, has opened 443 to its providers by default since it was added.
- **Exposure through an Ingress only.** No Gateway API route, the API most new clusters and controllers expose.
- **Metrics through `prometheus.io` annotations only**, which VictoriaMetrics reads and the Prometheus Operator ignores. A ServiceMonitor cannot help: port 8081 is on no Service, by design.
- **LiteLLM's image ran as root.** A namespace that enforces the `restricted` Pod Security Standard refused the pod, and OpenShift's restricted-v2 SCC runs it as an arbitrary user that cannot write the image's tree.
- **Fixed users on OpenShift.** The server's and the model port's `runAsUser`, `runAsGroup` and `fsGroup` (10001) are outside every OpenShift namespace's range, which restricted-v2 refuses; and the DNS rule named `kube-dns` in `kube-system`, where OpenShift runs none.
- **Smaller ones.** `trustedProxies` matched RFC 1918 only, so on EKS custom networking (`100.64.0.0/10`) or an IPv6 cluster every client looked like the controller to the login throttle; `strategy: {type: Recreate}` failed at the API server unless the operator also set `rollingUpdate: null`; the image tag was the top-level `imageTag` only, named for tools that rewrite one top-level line of a values file; and a chart published for `main` defaulted to `v<appVersion>`, an image that does not exist.

## Decision

**Every default works on a conformant Kubernetes cluster that the chart knows nothing about, and stays as narrow as that allows; what only the operator knows, the operator narrows, and the install notes say what is still open.**

1. **Port 8080 until the controller is named.** `networkPolicy.ingress.controller` defaults to empty, and then the policy admits port 8080, and only port 8080, from any source. Naming the controller's pods closes it to everything else, as before. The install notes warn while it is empty. Port 8081, LiteLLM's port 4000 and the model port keep their rules: none of them depends on the controller.
2. **Https to public addresses.** `networkPolicy.egress.systems` opens port 443 to `0.0.0.0/0` and `::/0` except the private (RFC 1918, `fc00::/7`, the deprecated `fec0::/10`), shared (`100.64.0.0/10`), loopback, link-local, unspecified and multicast ranges, the ranges the server's own guard refuses for a system unless the operator allows them (threat model 8.8), and ranges the guard does not know: the reserved `240.0.0.0/4`, which some clouds let a VPC use privately; the special-use ranges no internet host is in, which a private network may route (RFC 6890: the IETF protocol assignments `192.0.0.0/24`, benchmarking `198.18.0.0/15`, the documentation ranges `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` and `2001:db8::/32`, and the discard-only `100::/64`); and the local-use translation prefix `64:ff9b:1::/48`, which may carry private IPv4 addresses (RFC 8215). *The server's guard refuses these ranges too since 2026-10-24, and checks an address of `64:ff9b::/96` as the IPv4 address it embeds (threat model 8.8).* NAT64's well-known `64:ff9b::/96` stays open: it never carries a private IPv4 address (RFC 6052), and an IPv6-only cluster reaches IPv4 hosts through it. `to: []` drops it; a system inside the network still needs a rule in `networkPolicy.egress.extra`.
3. **Gateway API.** `httpRoute.*` renders an `HTTPRoute` (`gateway.networking.k8s.io/v1`) to the Service's port 8080, and with `redirectParentRefs` a second route on the Gateway's http listener that redirects to https, the counterpart of the Traefik Middleware: the session cookie is `Secure`. `publicUrl` falls back to `https://` and the route's first hostname.
4. **A PodMonitor.** `metrics.podMonitor.*` renders a `monitoring.coreos.com/v1` PodMonitor on the management port, which the VictoriaMetrics operator also converts. The annotations stay for scrapers that read them.
5. **Restricted pods everywhere.** LiteLLM runs from its non-root image, `ghcr.io/berriai/litellm-non_root`, the same release as `ghcr.io/berriai/litellm`, as user 65534 with a read-only root filesystem, `/tmp` an `emptyDir` and `XDG_CACHE_HOME` under it, in the chart and in Compose alike, so that the two keep one pin. Every pod of the chart meets the `restricted` Pod Security Standard.
6. **OpenShift.** `openshift: auto` turns on when the cluster serves `security.openshift.io/v1` (`true` and `false` set it). Then the chart leaves `runAsUser`, `runAsGroup` and `fsGroup` out of every security context it renders, so that the SCC assigns them, and adds OpenShift's DNS (`openshift-dns`, port 5353) to both policies' DNS rule. OpenShift turns the Ingress into a Route itself, so the chart renders no Route.
7. **The image tag under both names.** `image.tag` is the conventional name, `imageTag` stays for tools that rewrite one top-level line of a values file; the chart refuses both set to different tags. A chart published for `main` carries `appVersion: sha-<commit>`, and the default tag is `appVersion` as it is when it does not start with a digit, so the chart runs its own commit's images (amends ADR-0080). *Amended by ADR-0091: `imageTag` is gone; the one name is `image.tag`.*
8. **Both IP families.** Every rule that defaults to any address, the database's, the OIDC issuers', the SAML metadata's, the systems' and LiteLLM's providers', has an IPv6 peer beside the IPv4 one, so the defaults hold on IPv6-only and dual-stack clusters too. A cluster without IPv6 ignores those peers.
9. **The rest.** `trustedProxies` also matches `100.64.0.0/10` and `fc00::/7`; a `Recreate` strategy drops `rollingUpdate`.

## Consequences

- `helm install` with the Secrets and a database is enough on any cluster with any controller: nothing in the chart's defaults has to match the cluster for the server to be reachable and to reach its systems.
- Until the operator names the controller, any pod in the cluster can reach port 8080 and set the client IP behind `X-Forwarded-For` that the login throttle counts (threat model 1.5). The install notes, the public guide and the threat model say so, and the guide lists the selectors of common controllers. The password checks, the per-email throttle and every other control of port 8080 hold either way: the port is the one every user reaches through the ingress anyway.
- The server may reach any public address on 443 by default, where before it reached none but the OIDC issuers'. Its guard against private addresses, redirects and plain http is unchanged and still decides which systems it calls; an operator who wants an allow-list narrows `systems.to` to an egress proxy.
- An install that already names its controller and adds egress rules of its own, such as one for GitHub, renders the same policy plus the systems rule, which those rules may already cover, and LiteLLM restarts from the non-root image on its existing database. Its values need not change.
- A LiteLLM bump moves two pins in one pull request, Compose's (which Dependabot bumps) and the chart's, as before, now of the non-root image; CI's pin check compares them.
- `openshift: auto` decides from Helm's capabilities: `helm template` without `--api-versions security.openshift.io/v1` renders for a cluster that is not OpenShift. The OpenShift rendering is checked against the Kubernetes API and Pod Security admission, not on an OpenShift cluster.
- Charts published for `main` before this change keep `Chart.yaml`'s `appVersion`, and with it an image that does not exist.

## Alternatives considered

- **Another default controller, or a list of common controllers' labels.** Any one name is wrong on most clusters, and a list across all namespaces admits any pod that copies a label, while cloud load balancers and Cilium send from addresses or the agent, which no pod selector names.
- **Refusing to render without a controller.** Safe, but the chart then refuses `helm install` until the operator learns a selector, and a Gateway or load balancer that is no pod has none to give.
- **The NetworkPolicy off by default**, as most public charts do. It would drop the egress rules and LiteLLM's isolation, which work on every cluster, together with the one rule that cannot.
- **Egress closed by default, with a louder note.** The server's work is calling the company's systems; a default that times out every one of them is the first failure every operator meets, and the server's own guard already refuses private targets.
- **LiteLLM's root image by default, with the non-root one as an option.** The non-root image does all the server asks of LiteLLM (migrations, models, teams, keys, budgets, completions, the token counter, the admin UI), so there is no reason to default to root.
- **An OpenShift Route template.** OpenShift already turns an Ingress into a Route, with the annotation `route.openshift.io/termination`; a second template would duplicate the Ingress's values.
- **`image.tag` only.** A tool that rewrites one top-level line of a values file cannot rewrite a nested key, nor one under an umbrella chart's key (ADR-0080's alternatives).
