The design of the restart of 2026-10-05 is archived at [archive/v2/PLATFORM.md](../archive/v2/PLATFORM.md). The binding rules are in [CONVENTIONS.md](../CONVENTIONS.md).

## Status values

| Status | Meaning |
|---|---|
| Proposed | The decision is made but not built yet, or it is proposed to the maintainer and not accepted yet. |
| Accepted | The decision is in force and built. When a part of it is not built, the status line names that part ("Accepted (… not built: …)"). |
| Superseded | A later ADR replaces it. The later ADR links back. |

A later ADR that changes only part of a decision says so in its header ("Amends" or "Changes"), and the earlier ADR gets an "Amended by" line that links to it. Neither is a status.

## Format

Each ADR has these parts:

- **Header:** title, status, date, who decided, and sources (PLATFORM.md and CONVENTIONS sections, numbered as they stood on the ADR's date; the earlier versions of both are in [archive/](../archive/)).
- **Context:** the problem and the forces.
- **Decision:** what we do, stated in active voice.
- **Consequences:** what follows, good and bad.
- **Alternatives considered:** the options we did not take, and why.

The ADRs derive their rationale from the design (PLATFORM.md) and CONVENTIONS. Where the design names no alternative, an ADR states the obvious alternative and marks it "not discussed" in the design.

## Add an ADR

1. Copy the structure of an existing ADR. Use the next free number and a short kebab-case name: `NNNN-short-name.md`.
2. Set the status to Proposed.
3. Add the ADR to the index in this file.
4. Open a pull request. The maintainer accepts or rejects it.
5. When the decision is built, set its status to Accepted, in the file and in the index.
6. Never rewrite an accepted ADR. To change a decision, write a new ADR and mark the old one Superseded, or, when the new ADR changes only part of it, add an "Amended by" line to the old one.
